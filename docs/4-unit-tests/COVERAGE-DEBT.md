# 覆盖债台账

验不到或暂时没验的风险路径。补上有意义的验证时，同一次改动里删掉对应行。

| 路径 | 为什么难验 | 打算怎么解决 |
| --- | --- | --- |
| `lib/api.js` 路由层（鉴权、分页、建链回写） | 只有 `node:test` 单元测试与手工 curl，没有起 Express 的集成测试 | 用 `node:test` + 内置 `http` 起一个带假小码客户端的实例跑请求 |
| `lib/feishu_auth.js` 的 `signState` / `verifyState` | 未 export | export 后测过期 / 篡改 / 换租户 |
| 飞书端内 SSO 免登 | 只能在真实飞书客户端跑 | 保持人工验证，改 cookie / session 时强制走一遍 |
| 富的关联组织共享登录 | 需要富的真实账号 | 正式开放前验收并核对 `tenant_key` |
| 小码 webhook 真实推送 | 小码后台尚未配置回调；本地只用签名样例验过 | 配置后看详情页「实时事件」与 `/api/admin/events` |
| 同步引擎长期运行（熔断恢复、`missing_since` 标记上游删除的短链） | 需要上游真的出错 / 真的删链 | 观察生产 `sync_runs`；删链场景可在「短链测试」分组删组后看 |
| 概览「我的」范围超过 200 条个人短链 | 当前无人达到 | 到量后改为按创建者维度的每日聚合表 |

底线（不许欠账）：鉴权与越权、key 不下发、删除 / 持久化行为、发给小码的请求形状、webhook 验签，每次碰到都必须真实验证。
